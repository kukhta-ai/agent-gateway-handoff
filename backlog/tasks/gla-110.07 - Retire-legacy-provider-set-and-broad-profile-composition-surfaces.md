## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Remove or isolate the legacy composition surfaces after registry, deployment configuration, capsule composition, catalog, and provisioning have new owners.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Public app composition no longer requires AppProviderSet as the central provider-layer input for booting or provisioning the app.
- [x] #2 Broad ProviderSelectionProfile and ProviderProfileManifest are no longer accepted as the primary runtime shape for selecting both app infrastructure and capsule providers together.
- [x] #3 Legacy provider-set callback seams for defaultConfig, defaultServices, entrypointClientAssets, and templateProbes are removed from runtime composition or isolated behind a documented compatibility adapter.
- [x] #4 Reference provider packages expose registry/bootstrap data, deployment defaults, and capsule template defaults through the refactored model while preserving the named reference scenarios users already rely on.
- [x] #5 Import-boundary checks show that new code paths do not depend on legacy provider-set/profile composition types outside the compatibility boundary.
<!-- AC:END -->
