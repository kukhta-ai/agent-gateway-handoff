## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Give runtime users and their agents an executable flow for discovering available providers, understanding defaults, and choosing capsule providers for a session.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A runtime consumption flow is documented and executable for listing and inspecting available capsule provider capabilities by provider family and provider id.
- [x] #2 Runtime users can see the selected default provider for each popular user-facing capsule layer, the source of that default, and any evidence or compatibility condition affecting it.
- [x] #3 Runtime capsule provider overrides are accepted only for capsule provider families and cannot accidentally change AuthProvider, ChannelAdapter, or SecretStore deployment selection.
- [x] #4 Runtime diagnostics distinguish unavailable, not installed, incompatible, evidence-missing, and ambiguous-default outcomes in terms a user or runtime agent can act on.
- [x] #5 Runtime UX docs do not name CLI commands or flows that are unavailable in the implemented CLI or supported runtime API.
<!-- AC:END -->
