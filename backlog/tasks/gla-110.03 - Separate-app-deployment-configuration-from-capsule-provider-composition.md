## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Create a distinct app deployment selection model for providers that run the app itself, while keeping capsule provider choices in assembly/template composition.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The app exposes a deployment configuration surface for AuthProvider, ChannelAdapter, SecretStore, and their app-level defaults without including Launcher, Workspace, HumanEntrypoint, AgentConnector, or CompletionDetector selections.
- [x] #2 Capsule assembly and template inputs expose Launcher, Workspace, HumanEntrypoint, AgentConnector, and CompletionDetector choices without carrying AuthProvider, ChannelAdapter, or SecretStore selections.
- [x] #3 Runtime provider-id overrides preserve named deployment defaults, provider configuration, and SecretStore selection instead of rebuilding a synthetic profile that drops them.
- [x] #4 Enrollment policy parsing and diagnostics use the resolved deployment AuthProvider selection, including profile-selected delegated auth providers without requiring the legacy auth-provider flag.
- [x] #5 The existing reference scenarios are expressible as app deployment configuration plus capsule composition defaults, with unchanged externally observable defaults.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-06-16: Starting after GLA-110.02 completed and merged. This story separates app deployment provider selection (AuthProvider, ChannelAdapter, SecretStore) from capsule provider composition (Launcher, Workspace, HumanEntrypoint, AgentConnector, CompletionDetector) according to docs/architecture/provider-layer-refactor-contract.md.

2026-06-16 implementation: added AppDeploymentConfig/AppDeploymentConfigInput for AuthProvider, ChannelAdapter, SecretStore, and app-level providerConfig; added CapsuleProviderSelection/CapsuleProviderSelectionInput for Launcher, Workspace, HumanEntrypoint, AgentConnector, and CompletionDetector. Runtime composition now resolves deployment and capsule selections separately while keeping ProviderSelectionProfile as a migration adapter. createApp, createProvisioningBridge, createEnrollmentStack, and serve forward and consume the split surfaces; providerConfig treats deployment/profile config as defaults while preserving explicit config and provider-set opt-out semantics.

2026-06-16 verification: focused tests passed for app deployment config, auth provider selection, daemon split forwarding, and provisioning. pnpm gate passed after reviewer fix with typecheck, Biome, browser E2E preflight, and Vitest 81 files / 887 passed / 15 skipped. Reviewer Goodall initially found a serve() forwarding blocker for appDeploymentConfig/capsuleProviders; fix added daemon forwarding, appDeploymentConfig.providerConfig auth config resolution, and daemon regressions for both split surfaces. Re-review approved with no blocking findings.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Separated app deployment provider selection from capsule provider selection for runtime composition. Public app APIs now expose AppDeploymentConfig for AuthProvider, ChannelAdapter, SecretStore, and providerConfig, plus CapsuleProviderSelection for Launcher, Workspace, HumanEntrypoint, AgentConnector, and CompletionDetector. Runtime overrides preserve named deployment defaults/config/SecretStore, enrollment policy parsing uses the resolved deployment auth provider, and daemon serve forwards the split config into the live stack. Added focused integration coverage and passed the full gate after independent re-review approval.
