## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make provider and template authoring concrete enough for an operator agent to create or validate packages without guessing the extension seam.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Provider package validation reports manifest, family contract, schema, probe, skills or docs, dependency, redaction, and contract-test violations with stable diagnostics.
- [ ] #2 Template package validation reports catalog entity, schema, defaults, compatibility, skills or docs, and template-level dependency violations with stable diagnostics.
- [ ] #3 Provider and template authoring surfaces produce or validate package skeletons that do not require edits to generic app composition or narrow-waist packages.
- [ ] #4 Host-touching provider authoring identifies required WPM bundle metadata or skeleton requirements before the provider can be selected as available.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Depends on package contracts and named profiles.

Provider and template authoring surfaces must be shaped by the three explicit UX design tasks: provider authoring, operator install/update, and runtime consumption.
<!-- SECTION:NOTES:END -->
