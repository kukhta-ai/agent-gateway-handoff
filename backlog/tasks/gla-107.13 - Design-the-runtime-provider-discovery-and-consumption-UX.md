## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Design the runtime-agent experience for discovering registered providers and templates, understanding schemas and skills, dry-running proposals, and submitting sessions.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The runtime consumption UX identifies its protagonist, entry points, catalog/schema/template/skill reads, dry-run flow, proposal flow, success state, and handoff back to task execution.
- [x] #2 The UX describes how available, degraded, unavailable, incompatible, and policy-rejected providers or templates are explained to the runtime agent.
