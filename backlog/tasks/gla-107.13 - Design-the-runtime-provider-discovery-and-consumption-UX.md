## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Design the runtime-agent experience for discovering registered providers and templates, understanding schemas and skills, dry-running proposals, and submitting sessions.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The runtime consumption UX identifies its protagonist, entry points, catalog/schema/template/skill reads, dry-run flow, proposal flow, success state, and handoff back to task execution.
- [ ] #2 The UX describes how available, degraded, unavailable, incompatible, and policy-rejected providers or templates are explained to the runtime agent.
- [ ] #3 The UX defines diagnostics and recovery paths for unavailable providers, incompatible selections, schema errors, template-fixed override attempts, missing skills, and dry-run admission failures.
- [ ] #4 Write restrictions for provider code, profiles, WPM receipts, and daemon config are documented as UX constraints within the runtime-consumption journey, not as the journey structure itself.
<!-- AC:END -->



## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Added after user feedback that runtime provider discovery and consumption is its own UX flow, with catalog/schema/template/skill discovery and dry-run proposal recovery designed explicitly.
