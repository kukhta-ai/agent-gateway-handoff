## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Give provider authors and their agents an executable flow for creating, validating, testing, and inspecting provider packages against the registry/template contracts.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A provider authoring flow is documented and executable for creating a provider package for a specific provider family without requiring edits to unrelated app deployment or capsule layers.
- [x] #2 Generated provider and template packages use fields consumed by the refactored registry, catalog, compatibility, and template-resolution paths.
- [x] #3 Authoring validation reports duplicate provider ids, duplicate versions, duplicate template ids, unknown compatibility relation keys, missing required parts, and inert or unsupported fields as actionable diagnostics.
- [x] #4 A locally authored provider can be registered into a development boot context and appear in the catalog with its family, version, defaults, compatibility, and evidence state visible.
- [x] #5 Provider authoring docs do not name CLI commands or flows that are unavailable in the implemented CLI or supported developer surface.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-06-16 implementation: promoted provider and template-package authoring from deferred UX names into executable JSON-first CLI flows. Added provider/template scaffold, validate, test preflight, and inspect commands backed by catalog authoring helpers; scaffold output stays package-owned and excludes narrow-waist/app/capsule edits. Added workspace-level authoring validation for duplicate provider ids, duplicate provider id/version pairs, and duplicate template ids; tightened template authoring diagnostics for unsupported unprefixed template default keys; retained unknown compatibility relation, missing requiredParts, redaction, dependency, schema, docs/skills, and narrow-waist diagnostics. Updated provider authoring docs and CLI docs to match implemented commands and preflight semantics. Added ProviderRegistry dev boot proof for a locally authored launcher module selected through createBridge and visible through catalog/template output with family, version, resolved config/default/defaultSource/compatibility/provenance/probe evidence. Independent reviewer Goodall requested changes twice; fixes were applied and final re-review approved. Verification: pnpm run typecheck passed; focused Vitest provider authoring/CLI/app registry suites passed with 107 tests; pnpm run gate passed with typecheck, Biome CI, required browser preflight, and 81 test files / 913 passed / 15 skipped.
<!-- SECTION:NOTES:END -->
