## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Give provider authors and their agents an executable flow for creating, validating, testing, and inspecting provider packages against the registry/template contracts.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A provider authoring flow is documented and executable for creating a provider package for a specific provider family without requiring edits to unrelated app deployment or capsule layers.
- [ ] #2 Generated provider and template packages use fields consumed by the refactored registry, catalog, compatibility, and template-resolution paths.
- [ ] #3 Authoring validation reports duplicate provider ids, duplicate versions, duplicate template ids, unknown compatibility relation keys, missing required parts, and inert or unsupported fields as actionable diagnostics.
- [ ] #4 A locally authored provider can be registered into a development boot context and appear in the catalog with its family, version, defaults, compatibility, and evidence state visible.
- [ ] #5 Provider authoring docs do not name CLI commands or flows that are unavailable in the implemented CLI or supported developer surface.
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [ ] #1 Typecheck passes with no errors.
- [ ] #2 Linter passes clean.
- [ ] #3 Tests are added for the change and the full suite is green.
- [ ] #4 Public functions and exported types are documented.
- [ ] #5 No dead code or unused exports are introduced.
- [ ] #6 The core import-boundary holds: core depends only on ports, never on concrete adapters.
- [ ] #7 The provider authoring flow has an executable transcript, automated CLI/API coverage, or equivalent runnable proof attached to the task evidence.
- [ ] #8 A generated provider package fixture validates successfully and appears in a development catalog with family, version, defaults, compatibility, and evidence state.
- [ ] #9 Authoring docs and help text are checked against the implemented command/API surface so stale command names are not introduced.
<!-- DOD:END -->
