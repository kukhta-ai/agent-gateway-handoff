## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make capsule admission resolve against the catalog and make runtime provisioning consume the resolved capsule plan, while app infrastructure providers come from deployment configuration.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Admission accepts capsule assembly/template inputs and catalog capabilities, then returns a resolved capsule plan containing selected capsule provider ids, provider configuration, compatibility decisions, and evidence requirements.
- [x] #2 Runtime provisioning creates Launcher, Workspace, HumanEntrypoint, AgentConnector, and CompletionDetector providers from the resolved capsule plan rather than from a broad provider profile.
- [x] #3 App boot creates AuthProvider, ChannelAdapter, and SecretStore providers from deployment configuration rather than from capsule admission or assembly inputs.
- [x] #4 Asynchronous provider factories are usable in the app boot/provisioning path where the caller can await them, and any remaining synchronous-only path reports an explicit unsupported-provider diagnostic.
- [x] #5 Admission and provisioning diagnostics distinguish not installed, incompatible, unavailable by evidence, missing default, and ambiguous default outcomes for capsule providers.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented resolved capsule plan flow across admission, bridge, session, worker, and app composition. Admission now returns capsule_plan with provider ids/config/evidence/diagnostics; bridge/CLI expose it; sessions persist it; provisioning creates capsule providers from the resolved plan and deployment providers from deployment config. Added awaited async capsule provider coverage plus sync-only provider.async_unsupported boot diagnostic coverage. Fixed review blockers for plan-scoped launcher teardown, workspace config/restart rehydration, and open-part overrides when default providers are unavailable.
