## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make capsule admission resolve against the catalog and make runtime provisioning consume the resolved capsule plan, while app infrastructure providers come from deployment configuration.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Admission accepts capsule assembly/template inputs and catalog capabilities, then returns a resolved capsule plan containing selected capsule provider ids, provider configuration, compatibility decisions, and evidence requirements.
- [ ] #2 Runtime provisioning creates Launcher, Workspace, HumanEntrypoint, AgentConnector, and CompletionDetector providers from the resolved capsule plan rather than from a broad provider profile.
- [ ] #3 App boot creates AuthProvider, ChannelAdapter, and SecretStore providers from deployment configuration rather than from capsule admission or assembly inputs.
- [ ] #4 Asynchronous provider factories are usable in the app boot/provisioning path where the caller can await them, and any remaining synchronous-only path reports an explicit unsupported-provider diagnostic.
- [ ] #5 Admission and provisioning diagnostics distinguish not installed, incompatible, unavailable by evidence, missing default, and ambiguous default outcomes for capsule providers.
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [ ] #1 Typecheck passes with no errors.
- [ ] #2 Linter passes clean.
- [ ] #3 Tests are added for the change and the full suite is green.
- [ ] #4 Public functions and exported types are documented.
- [ ] #5 No dead code or unused exports are introduced.
- [ ] #6 The core import-boundary holds: core depends only on ports, never on concrete adapters.
- [ ] #7 An integration path proves admission returns a resolved capsule plan and provisioning consumes that plan for capsule providers.
- [ ] #8 App boot coverage proves AuthProvider, ChannelAdapter, and SecretStore are created from deployment configuration outside capsule admission.
- [ ] #9 Async provider behavior is covered by a usable awaited factory path or an explicit synchronous-only unsupported diagnostic.
- [ ] #10 Provisioning diagnostics are covered for not installed, incompatible, evidence-missing, missing default, and ambiguous default outcomes.
<!-- DOD:END -->
