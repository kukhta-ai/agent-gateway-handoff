## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Give operators and their agents an executable flow for installing, updating, checking, and rolling back provider packages on a deployment.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 An install/update flow is documented and executable for adding or updating provider packages on a deployment without requiring provider authoring steps.
- [ ] #2 Before activation, the flow reports which registry entries, deployment defaults, capsule template defaults, compatibility relations, and evidence requirements would change.
- [ ] #3 The flow rejects incompatible, duplicate, unsigned or unverifiable, and evidence-missing provider packages with diagnostics that identify the affected provider family and layer.
- [ ] #4 A provider graph doctor or equivalent diagnostic surface is executable and reports the installed provider inventory, selected app deployment providers, selected capsule defaults, and unresolved compatibility/evidence problems.
- [ ] #5 The install/update flow makes clear when the same physical agent is acting as an operator/deployment agent rather than as a provider author or runtime capsule consumer.
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [ ] #1 Typecheck passes with no errors.
- [ ] #2 Linter passes clean.
- [ ] #3 Tests are added for the change and the full suite is green.
- [ ] #4 Public functions and exported types are documented.
- [ ] #5 No dead code or unused exports are introduced.
- [ ] #6 The core import-boundary holds: core depends only on ports, never on concrete adapters.
- [ ] #7 Install/update coverage includes a successful activation preview and rejected incompatible, duplicate, unverifiable, and evidence-missing package cases.
- [ ] #8 Doctor or equivalent diagnostics are verified against an installed inventory that includes deployment providers, capsule defaults, and unresolved graph problems.
- [ ] #9 Rejected install/update attempts leave the previously active provider inventory and defaults observable and unchanged.
- [ ] #10 Operator UX copy distinguishes install/update work from provider authoring and runtime consumption work.
<!-- DOD:END -->
