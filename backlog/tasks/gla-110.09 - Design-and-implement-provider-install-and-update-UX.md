## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Give operators and their agents an executable flow for installing, updating, checking, and rolling back provider packages on a deployment.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 An install/update flow is documented and executable for adding or updating provider packages on a deployment without requiring provider authoring steps.
- [x] #2 Before activation, the flow reports which registry entries, deployment defaults, capsule template defaults, compatibility relations, and evidence requirements would change.
- [x] #3 The flow rejects incompatible, duplicate, unsigned or unverifiable, and evidence-missing provider packages with diagnostics that identify the affected provider family and layer.
- [x] #4 A provider graph doctor or equivalent diagnostic surface is executable and reports the installed provider inventory, selected app deployment providers, selected capsule defaults, and unresolved compatibility/evidence problems.
- [x] #5 The install/update flow makes clear when the same physical agent is acting as an operator/deployment agent rather than as a provider author or runtime capsule consumer.
<!-- AC:END -->
