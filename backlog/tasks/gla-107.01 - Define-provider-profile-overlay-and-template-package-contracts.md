## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Establish the manifest and validation contracts that make provider profiles, profile overlays, and template packages concrete implementation inputs.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 ProviderProfile and ProviderProfileOverlay inputs are validated against versioned schemas covering canonical family ids, inheritance, cardinality, provider-id resolution, config refs, disabled or null provider behavior, and unknown keys.
- [x] #2 Profile overlay inheritance cycles, wrong-family provider selections, duplicate singleton selections, unresolved config refs, and literal or ad-hoc secret values are rejected with stable diagnostics.
- [x] #3 CapsuleTemplate packages are represented as catalog packages with schema, defaults, compatibility requirements, skills or docs, and tests, without requiring a Provider Host runtime factory.
- [x] #4 Operator-owned boot-time lifecycle for profiles and overlays is documented and reflected in validation diagnostics.
