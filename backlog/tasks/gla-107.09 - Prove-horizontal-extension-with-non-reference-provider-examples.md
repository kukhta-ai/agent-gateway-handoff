## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Demonstrate that a provider can be added horizontally through the supported package, profile, and install path without narrow-waist edits.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 At least one non-reference provider or template package for a popular user-facing layer is selected through a provider profile or overlay.
- [x] #2 The selected non-reference package appears in catalog, schema, skills or docs, doctor diagnostics, and dry-run admission with the same graph projection as reference providers.
- [x] #3 The relevant runtime or dry-run path uses the selected non-reference package without provider-specific imports in app, gateway, session, identity, worker core, or kernel.
- [x] #4 The extension example includes contract tests proving package validation, profile selection, compatibility, availability diagnostics, and redaction behavior.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->

App composition test extends the fake non-reference provider set with entrypoint schema/skills and proves createProvisioningBridge dry-run admission accepts browser-handoff through the selected fake entrypoint without app/gateway/session/identity/worker/kernel provider-specific imports.
