## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Finalize the provider-layer refactor by ending legacy compatibility support after the cross-layer refactor is verified. The completed state keeps the registry, deployment configuration, and capsule composition model as the only supported provider-layer path; old ProviderSet/Profile-era compatibility may remain only as archived migration history, not as executable runtime, authoring, install, or UX behavior.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Runtime provider selection has no supported path that accepts AppProviderSet, broad ProviderSelectionProfile/ProfileManifest, or provider-set callback seams for provider-layer composition.
- [ ] #2 Compatibility adapters, migration import exceptions, and verification allowlists for ProviderSet/Profile-era runtime composition are absent from runtime packages.
- [ ] #3 User-facing CLI help, provider UX documentation, and supported API documentation describe only registry, deployment configuration, and capsule composition paths, with no advertised legacy provider-set/profile fallback.
- [ ] #4 Reference local-dev, single-operator, delegated-auth, and custom-provider scenarios pass using the refactored provider-layer model only.
- [ ] #5 Boundary and regression checks fail if legacy provider-set/profile APIs are reintroduced as accepted runtime inputs or supported UX surfaces.
<!-- AC:END -->
