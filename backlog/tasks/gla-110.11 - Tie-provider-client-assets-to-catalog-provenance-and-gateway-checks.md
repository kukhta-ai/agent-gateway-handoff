## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make browser-facing provider assets part of the provider capability/evidence story instead of an implicit provider-set callback or unchecked local override.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Entrypoint client assets served by the gateway are traceable to a registry/catalog provider capability or an explicit local override with visible provenance.
- [ ] #2 The catalog or doctor surface reports whether a client asset source is packaged, evidence-backed, local override, read-only, mutable, or unverifiable.
- [ ] #3 A mutable or unverifiable alternate client asset root cannot be mistaken for packaged immutable provider evidence in runtime diagnostics.
- [ ] #4 Gateway behavior is covered for packaged assets, alternate asset roots, writable roots, missing roots, and evidence-backed asset sources.
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [ ] #1 Typecheck passes with no errors.
- [ ] #2 Linter passes clean.
- [ ] #3 Tests are added for the change and the full suite is green.
- [ ] #4 Public functions and exported types are documented.
- [ ] #5 No dead code or unused exports are introduced.
- [ ] #6 The core import-boundary holds: core depends only on ports, never on concrete adapters.
- [ ] #7 Gateway asset coverage includes packaged assets, alternate asset roots, writable roots, missing roots, and evidence-backed asset sources.
- [ ] #8 Catalog or doctor output exposes client asset provenance and mutability state for packaged and local override sources.
- [ ] #9 Local client asset overrides are visibly distinguished from packaged immutable provider evidence in diagnostics or docs.
<!-- DOD:END -->
