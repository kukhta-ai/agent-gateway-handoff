## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Bring architecture docs, UX docs, diagrams, and migration notes into alignment with the refactored provider-layer model.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Architecture docs and diagrams consistently use the refactored terms ProviderRegistry, AppDeploymentConfig, CapsuleTemplate/AssemblySpec, CapabilityCatalog, and Admission Resolver for their target responsibilities.
- [ ] #2 Legacy ProviderSet, broad ProviderProfile, ProviderHost, and ProviderRuntime terms are either removed from target architecture language or explicitly marked as compatibility/internal terms.
- [ ] #3 Migration guidance maps existing provider profiles, reference scenarios, CLI flags, provider-set callbacks, template defaults, and provider authoring fields to the new model.
- [ ] #4 Provider authoring, install/update, runtime consumption, doctor, and catalog documentation names only executable commands or supported APIs.
- [ ] #5 An architecture decision note records why registry plus deployment config plus capsule composition replaces the previous provider-set/profile layering.
<!-- AC:END -->

<!-- DOD:BEGIN -->

- [ ] #2 Linter passes clean.
