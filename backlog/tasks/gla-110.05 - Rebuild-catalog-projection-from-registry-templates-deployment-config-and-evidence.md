## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make the provider catalog a read-only capability projection over registered providers, capsule templates, app deployment configuration, and runtime evidence.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A resolved catalog view is derivable from ProviderRegistry data, capsule templates, app deployment configuration, WPM evidence, and probes without requiring AppProviderSet profile/default callbacks.
- [ ] #2 The catalog reports availability, default source, compatibility constraints, package provenance, and evidence state for providers and templates across app-infrastructure and capsule provider families.
- [ ] #3 Default provider packages for the popular user-facing capsule layers are visible as computed catalog outcomes with their source of selection.
- [ ] #4 Unknown compatibility relation keys, invalid relation targets, and ambiguous compatibility declarations surface as catalog diagnostics instead of being silently ignored.
- [ ] #5 Catalog behavior is covered for duplicate inputs, missing defaults, compatibility ambiguity, evidence-gated availability, and reference-package defaults.
<!-- AC:END -->
