## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make the runtime surfaces consume the same resolved provider graph rather than carrying separate compatibility or availability rules.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Catalog, Doctor, Provider Host boot, and Admission observe the same provider and template availability, compatibility, and diagnostic outcomes for a selected profile.
- [ ] #2 Dry-run Admission rejects unavailable providers, unavailable template-level dependencies, incompatible provider combinations, and template-fixed security overrides before task, session, route, or capsule creation.
- [ ] #3 Provider Host creates runtime ports only for providers that are selected, registered, configured, available, and compatible in the resolved graph.
- [ ] #4 Existing reference-provider behavior remains available through the selected reference profile.
<!-- AC:END -->
