## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Design the operator/operator-agent experience for choosing, configuring, verifying, updating, and rolling back provider sets, profiles, overlays, and host dependency evidence.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The operator install/update UX identifies its protagonist, entry points, profile and overlay inputs, WPM touchpoints, doctor evidence, success state, rollback state, and handoff to runtime consumption.
- [ ] #2 The UX describes how named profiles are selected and how profile-specific defaults are explained without global default ambiguity.
- [ ] #3 The UX defines diagnostics and recovery paths for unavailable dependencies, invalid overlays, unresolved secret refs, failed WPM probes, degraded runtime probes, and unsafe public-edge transport evidence.
- [ ] #4 Write permissions, guarded operations, and rollback limits are documented as UX constraints within the install/update journey, not as the journey structure itself.
<!-- AC:END -->



## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Added after user feedback that install/update is a distinct UX flow even if the same agent performs it on the operator VPS.
