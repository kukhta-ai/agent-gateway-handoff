## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Design the developer/operator-agent experience for creating a provider package or template package that is complete, testable, and reviewable.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The provider authoring UX identifies its protagonist, entry points, primary commands or screens, package inputs, validation checkpoints, success state, and handoff to operator install/update.
- [ ] #2 The UX covers provider package and template package authoring without treating CapsuleTemplate as a Provider Host runtime factory.
- [ ] #3 The UX defines diagnostics and recovery paths for missing manifest fields, invalid schemas, missing skills or docs, missing probes, dependency requirements, redaction failures, and contract-test failures.
- [ ] #4 Write permissions and guarded operations are documented as UX constraints within the provider-authoring journey, not as the journey structure itself.
<!-- AC:END -->



## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Added after user feedback that the provider graph work must design the three flows as distinct UX/developer-UX experiences. Provider authoring is the developer/operator-agent package-creation experience.
<!-- SECTION:NOTES:END -->
