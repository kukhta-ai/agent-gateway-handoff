## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Design the developer/operator-agent experience for creating a provider package or template package that is complete, testable, and reviewable.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The provider authoring UX identifies its protagonist, entry points, primary commands or screens, package inputs, validation checkpoints, success state, and handoff to operator install/update.
- [x] #2 The UX covers provider package and template package authoring without treating CapsuleTemplate as a Provider Host runtime factory.
- [x] #3 The UX defines diagnostics and recovery paths for missing manifest fields, invalid schemas, missing skills or docs, missing probes, dependency requirements, redaction failures, and contract-test failures.
- [x] #4 Write permissions and guarded operations are documented as UX constraints within the provider-authoring journey, not as the journey structure itself.
<!-- AC:END -->
